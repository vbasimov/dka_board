# Архитектура решения (черновик для согласования)

Документ этапа 1. Описывает, из чего состоит продукт и где проходят границы. Не описывает код.

## 1. Компоненты

```
┌─────────────────────────────────────────────────────┐
│  Интерфейс (статичные файлы)                        │
│  HTML + CSS + модули JS, без сборки и без CDN       │
└───────────────────────┬─────────────────────────────┘
                        │ запросы на 127.0.0.1
┌───────────────────────▼─────────────────────────────┐
│  Локальный помощник (node)                          │
│  файловый доступ · вызов gigacode · MCP-клиент      │
│  разбор draw.io · сверка версий · индексы           │
└───────────────────────┬─────────────────────────────┘
                        │ чтение и запись
┌───────────────────────▼─────────────────────────────┐
│  Папка данных                                       │
│  Markdown с frontmatter · индексы JSON · кэш КАФО   │
└─────────────────────────────────────────────────────┘
```

**Почему нужен локальный помощник.** Открытый напрямую файл `index.html` не может читать и записывать папку с данными: браузеры блокируют файловые запросы из соображений безопасности. Есть два выхода: помощник на `127.0.0.1` (работает во всех браузерах, доступ к файлам полный) или File System Access API (только Chrome и Edge, Firefox выпадает, а разрешение пользователь выдаёт заново после перезапуска). Рекомендация — помощник; он не выходит в сеть, слушает только локальный адрес и запускается ярлыком вместе с интерфейсом.

Это уточняет решение D3 из интента: «без сервера» означало «без инфраструктуры и без сетевого сервиса», а не «без процесса-помощника». Требование «ноль внешних вызовов» сохраняется: помощник не делает исходящих соединений, кроме `127.0.0.1`.

## 2. Границы ответственности

| Слой | Отвечает | Не отвечает |
|---|---|---|
| Интерфейс | показ, ввод, навигация, копирование | чтение файлов, вызовы модели, разбор схем |
| Помощник | файлы, индексы, разбор draw.io, сверка версий, вызов gigacode, MCP | вёрстка, тексты подсказок |
| Папка данных | хранение и переносимость | правила доступа |
| gigacode | генерация и извлечение | хранение, проверка источников |

Правило: **всё, что можно проверить без модели, проверяется без модели.** Классификация писем по правилам, подсчёт сроков, сверка версий, поиск по индексу — детерминированный код. Модель подключается там, где нужен текст: черновик ответа, извлечение факта из абзаца, ревью.

## 3. Папка данных

```
Данные/
  задачи/            2026-11-24-001.json или .md
  факты/             fact-<дата>-<номер>.md
  решения/           decision-<дата>-<номер>.md
  источники/         источники.md — реестр страниц, схем, писем
  кэш-кафо/          <page_id>/<version>.md + meta.json
  индексы/           задачи.json, факты.json, источники.json
  отчёты/            ревью-2026-11-24.md
  плагины/           <имя>/manifest.json + файлы плагина
  журнал.jsonl       журнал действий: что открывали, что подтверждали
```

- Факты и решения — Markdown с frontmatter, открываются в Obsidian.
- Задачи и индексы — JSON: их читает только программа, человеку они не нужны.
- `журнал.jsonl` нужен для аудита: какая версия источника и какой набор фактов использовались в ответе.

## 4. Локальный интерфейс помощника

Простые вызовы, только с `127.0.0.1`, без внешних зависимостей:

| Вызов | Что делает |
|---|---|
| `GET /api/state` | сводка для экрана «Сегодня» |
| `GET /api/tasks` | список задач с фильтрами |
| `POST /api/tasks` | создать задачу (источник обязателен) |
| `GET /api/cards/:id` | карточка: запрос, черновик, источники |
| `GET /api/cafo` | страницы КАФО со статусами |
| `POST /api/cafo/sync` | сверка версий и обновление кэша |
| `GET /api/diagrams` | схемы и расхождения |
| `GET /api/decisions` | журнал решений |
| `POST /api/review` | запуск ревью |
| `POST /api/plugins/:name/run` | вызов плагина |

Каждый ответ содержит `version` набора данных, чтобы интерфейс не показывал устаревшее.

## 5. Контракт плагина

```
плагины/<имя>/
  manifest.json   { name, version, apiVersion: "1", entry, commands[], hooks[] }
  index.js        точка входа, получает объект api
```

- `apiVersion` — мажорная версия контракта; ядро обещает не ломать её внутри мажорной.
- Плагин получает: чтение задач и фактов, запись своих файлов, вызов gigacode, показ панели.
- Плагину запрещено: сетевые вызовы, запись вне своей папки, изменение фактов без подтверждения человеком.
- Падение плагина перехватывается: ядро продолжает работу, в журнал пишется ошибка.

## 6. Технологический стек

| Часть | Выбор | Причина |
|---|---|---|
| Интерфейс | HTML, CSS, ES-модули | без сборки, открывается как статика |
| Помощник | Node.js 20+ (уже есть вместе с gigacode) | файлы, процессы, тесты без зависимостей |
| Тесты | `node --test` | встроено, не требует установки пакетов |
| Хранение | Markdown + JSON | переносимость, Obsidian, отсутствие СУБД |
| Модель | DeepSeek Flash 1017 через gigacode | единственный доступный интеллект в контуре |

Внешних зависимостей нет ни у интерфейса, ни у помощника: бандл собирается из файлов репозитория, без `npm install` в контуре.

## 7. Что проверяется спайками до разработки

1. Разбор draw.io: сколько рёбер извлекается корректно на 10 реальных схемах.
2. Сверка версий Confluence: работают ли 6 проверок, включая недоступность и переименование.
3. Запуск и хранение: стартует ли помощник у не-разработчика, держит ли 10 000 задач и 5 000 фактов.

Не пройден хотя бы один — меняем подход, а не «доделываем на ходу».

## 8. Открытый вопрос

**Q11.** Устраивает ли локальный помощник на `127.0.0.1`, запускаемый ярлыком? Альтернатива — File System Access API: без помощника, но только Chrome и Edge, и доступ к папке нужно подтверждать после каждого перезапуска. По умолчанию принимаю помощника.
