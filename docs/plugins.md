# Плагины: контракт API v1

Документ описывает расширение ядра (FR-37–FR-40): что кладёт автор в папку плагина, что плагин получает от ядра, чего ему делать нельзя и как ядро защищается от сбоев.

Плагины — необязательная часть. Без них помощник работает как обычно.

## 1. Где лежит плагин

Плагины живут в папке данных, рядом с задачами и фактами:

```
Данные/
  задачи/
  факты/
  плагины/
    hello/
      manifest.json     обязательный манифест
      index.js          точка входа
      привет.md         файлы, которые плагин пишет сам
```

Имя папки — удобный ярлык; идентификатор плагина задаёт поле `name` в манифесте. Два плагина с одинаковым `name` одновременно не загружаются: второй попадёт в `rejected`.

## 2. Манифест

`manifest.json` — JSON-объект:

```json
{
  "name": "hello",
  "version": "1.0.0",
  "apiVersion": "1",
  "entry": "index.js",
  "commands": [{ "id": "greet", "title": "Поздороваться" }],
  "hooks": ["onStart"]
}
```

| Поле | Обязательно | Правило |
|---|---|---|
| `name` | да | kebab-case: строчные латинские буквы и цифры через дефис, например `review-helper` |
| `version` | да | semver, например `1.0.0`, `2.1.0-beta.1` |
| `apiVersion` | да | строка; сейчас поддерживается только `"1"` |
| `entry` | да | относительный путь к файлу внутри папки плагина; `..` и абсолютные пути запрещены |
| `commands` | нет | массив `{id, title}`; `id` не повторяется, `title` видит человек |
| `hooks` | нет | массив из `onStart`, `onTaskCreated`, `onDraftBuilt`; в API v1 имена проверяются и сохраняются, но ядро пока не вызывает хуки — вызов идёт через `commands` |

Неизвестные поля манифеста игнорируются: это запас совместимости внутри мажорной версии API.

Ошибка в манифесте не останавливает загрузку остальных плагинов. Плагин попадает в `rejected`, а причина — в массив `errors` и в журнал ядра.

## 3. Точка входа

`entry` — ESM-модуль с экспортом по умолчанию:

```js
export default function (api) {
  return {
    commands: {
      // id команды из manifest.json → функция
      async greet(payload) {
        return { greeting: `Привет, ${payload?.name ?? 'архитектор'}!` }
      }
    }
  }
}
```

Ядро вызывает `commands[commandId](payload)` и возвращает полученное значение как результат `registry.run(...)`. Команда может быть синхронной или асинхронной. Фабрика вызывается один раз при первом запуске плагина.

Точка входа — ESM-модуль. Если папка данных лежит вне проекта с `"type": "module"` и используется Node.js 20, дайте файлу расширение `.mjs` или положите рядом `package.json` с `{"type": "module"}`.

## 4. Что плагин получает: объект `api`

Объект заморожен и содержит ровно четыре функции. Сетевых, процессных и файловых функций, кроме перечисленных, нет.

| Функция | Что делает |
|---|---|
| `readTasks()` | возвращает массив задач из `Данные/задачи/*.json`; повреждённые файлы пропускаются |
| `readFacts()` | возвращает массив фактов из `Данные/факты/*.json`; повреждённые файлы пропускаются |
| `writeOwnFile(name, content)` | пишет файл только внутри папки своего плагина, создаёт подпапки, возвращает абсолютный путь; `..`, абсолютные пути и запись через символическую ссылку запрещены |
| `log(message)` | пишет строку в журнал ядра с пометкой плагина; если журнала нет, вызов ничего не делает |

`content` — строка или `Buffer`; объект сериализуется в JSON с отступом 2. `readTasks()` и `readFacts()` возвращают копии, поэтому плагин не может незаметно изменить данные ядра.

Пример плагина (13 строк):

```js
// плагины/hello/index.js
export default function (api) {
  return {
    commands: {
      async greet(payload) {
        const tasks = api.readTasks()
        api.log(`приветствие, задач: ${tasks.length}`)
        api.writeOwnFile('привет.md', `# Привет\n\nЗадач: ${tasks.length}\n`)
        return { greeting: `Привет, ${payload?.name ?? 'архитектор'}!`, tasks: tasks.length }
      }
    }
  }
}
```

## 5. Что можно и что нельзя

Можно:

- читать задачи и факты;
- писать собственные файлы внутри своей папки;
- писать в журнал;
- возвращать результат команды.

Нельзя:

- делать сетевые вызовы — `fetch`, `http`, `https`, `http2`, `net`, `tls`, `dns`, `dgram`, `undici`, WebSocket и любые обёртки;
- запускать процессы и обращаться к внутренним модулям ядра;
- писать за пределы своей папки;
- менять факты и задачи без подтверждения человеком;
- блокировать цикл событий бесконечной синхронной работой.

### Сеть: позиция ядра

Ядро не предоставляет плагину ни одной сетевой функции. В объекте `api` нет `fetch`, `http` и их аналогов; «помочь» обойти запрет нечем.

Дополнительно реестр перед первым запуском читает `entry` и статически ищет импорты сетевых модулей. Если они есть, плагин не запускается, а отказ с текстом «запрещены сетевые вызовы (FR-38)» попадает в `errors`. Это проверка точки входа, а не песочница: глобальный `fetch` в Node существует, но его использование нарушает контракт и является основанием снять плагин с поддержки. Ядро такому плагину не помогает и ответственности за его сетевую активность не несёт.

## 6. Как ядро защищается от падения

- **Валидация при загрузке.** Каждый манифест проверяется до запуска. Невалидный плагин попадает в `rejected` с русской причиной; остальные загружаются.
- **Нет папки — нет проблемы.** Если папки `плагины` нет, `load()` возвращает пустые списки, это не ошибка.
- **Бросок перехватывается.** Ошибка команды или фабрики не выходит за пределы реестра: `run()` отклоняется с понятным текстом, событие пишется в `errors`, следующие вызовы работают.
- **Таймаут 2 секунды.** Загрузка модуля, вызов фабрики и выполнение команды ограничены 2 с. Зависшая асинхронная команда отклоняется, остальные плагины продолжают работать. Синхронный бесконечный цикл в одном потоке прервать нельзя — это прямое нарушение контракта.
- **Журнал.** Запись `errors` имеет вид `{ at, plugin, command, message }` и дублируется в `logger.error`, если журнал передан.

Пример:

```js
import { createPluginRegistry } from './src/plugins/registry.js'

const registry = createPluginRegistry({ dir: join(dataDir, 'плагины'), logger: console })
registry.load()
await registry.run('hello', 'greet', { name: 'Анна' })
```

Ошибки, которые видит вызывающий код:

- `плагин "hello" не найден` — неизвестное имя;
- `у плагина "hello" нет команды "greet"` — команда не объявлена в фабрике;
- `плагин "hello", команда "greet": ...` — команда бросила исключение или не ответила вовремя.

## 7. Версия API и совместимость (FR-40)

- `apiVersion` — мажорная версия контракта. Сейчас это `"1"`; другие значения отклоняются при загрузке.
- Внутри мажорной версии ядро не удаляет поля манифеста, не меняет смысл `api` и не ломает существующие команды. Новые необязательные поля и функции могут появляться в минорных версиях; плагин, который их не знает, продолжает работать.
- Версия самого плагина (`version`) живёт отдельно от `apiVersion`: плагин может выпускать мажорные версии, не меняя контракт.

### Миграция на новую мажорную версию API

1. Ядро объявляет `apiVersion: "2"` и публикует список изменений; `"1"` остаётся доступной в переходном релизе.
2. Автор меняет `apiVersion` в манифесте, правит вызовы и поднимает мажорную версию плагина.
3. Плагин с неподдерживаемым `apiVersion` не запускается и попадает в `rejected` с причиной — молчаливого выполнения «как получится» нет.
4. Откат: вернуть прежний `apiVersion` и версию плагина; данные в папке плагина не удаляются.

Правило для автора: не рассчитывайте на недокументированные поля ядра. Всё, что не описано здесь, может измениться без предупреждения.
