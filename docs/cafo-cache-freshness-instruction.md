# Инструкция: свежесть кэша КАФО в скилле выгрузки

Кому: владельцу скилла выгрузки КАФО из Confluence.
Что сделать: добавить в скилл проверку версии страницы перед использованием кэша, чтобы ответ никогда не выдавал устаревший факт за актуальный.
Ожидаемый объём: 10–20 строк кода проверки + раздел в SKILL.md. Без изменения формата фактов.

---

## 1. Зачем

Кэш стареет молча. Страницу правят в Confluence, скилл выгружает её по расписанию — и в момент ответа непонятно, кэш свежий или трёхдневной давности. Дата выгрузки врёт в обе стороны: кэш может быть свежим по времени и устаревшим по содержанию. Нужна сверка **номера версии страницы**, а не времени.

## 2. Что хранить в кэше

В метаданных каждого кэшированного документа (рядом с телом страницы):

```yaml
confluence:
  page_id: "123456789"          # неизменный идентификатор, не название
  title: "КАФО: Платежи"
  space_key: "ARCH"
  version: 12                    # version.number из API
  fetched_at: "2026-11-24T09:00:00+03:00"
  checked_at: "2026-11-24T09:00:00+03:00"   # последняя успешная сверка
  url: "https://confluence.internal/pages/viewpage.action?pageId=123456789"
  ancestors: ["КАФО", "Трайб B2C"]          # для агрегации по трайбу
```

Ключевое: `page_id` и `version`. Название страницы не является идентификатором — её могут переименовать и переместить.

## 3. Проверка перед использованием

Выполняется каждый раз, когда факт из КАФО попадает в ответ. Тянуть только метаданные, не тело страницы.

1. Взять `page_id` из кэша.
2. Запросить метаданные: `GET /rest/api/content/{page_id}?expand=version,history.lastUpdated`.
3. Сравнить `version.number` с сохранённым:
   - **равно** → статус `свежо`, обновить `checked_at`;
   - **больше** → статус `устарело`, сохранить новую версию, переиндексировать документ, старые факты помечить `superseded_by: <новый id факта>`;
   - **404 / нет ответа / нет прав** → статус `не сверено`, обновить `checked_at` не удалось.
4. Если страница переехала (сменился `space_key` или `ancestors`) — сохранить новый путь, но `page_id` не менять.

Таймаут проверки — 3 секунды. Недоступность Confluence не должна блокировать ответ: он выдаётся со статусом `не сверено`.

## 4. Как это выглядит в ответе

Одна строка под каждым обоснованием:

```
Источник: КАФО «Платежи», v12 от 05.11.2026, сверено 24.11.2026
```

```
⚠️ Источник: КАФО «Платежи», кэш v12 от 05.11.2026; в Confluence уже v14 (2 правки).
   Проверить страницу перед использованием в комитете.
```

```
⚠️ Источник: КАФО «Платежи», кэш v12 от 05.11.2026. Сверить с Confluence не удалось
   (нет доступа). Утверждение может быть устаревшим.
```

Статус `не сверено` показывается всегда, даже если `fetched_at` — минуту назад. Ложное «свежо» хуже честного «не знаю».

## 5. Фрагмент для SKILL.md

Вставить в скилл выгрузки новым разделом:

```markdown
## Свежесть кэша

Перед тем как использовать факт из кэша КАФО в ответе, сверь номер версии страницы.

- Храни `page_id` и `version` вместе с кэшем; название страницы идентификатором не является.
- Проверяй только метаданные: `GET /rest/api/content/{page_id}?expand=version,history.lastUpdated`, таймаут 3 секунды.
- Совпало — статус «свежо». Выросло — «устарело»: перекачай, переиндексируй, старые факты помечи `superseded_by`, сохрани ссылку на новую версию.
- Не ответил Confluence — статус «не сверено». Ответ выдаётся, но с предупреждением.
- В каждом обосновании — строка источника: страница, версия, дата сверки, статус.
- Никогда не помечай кэш «свежим» по дате выгрузки. Свежесть — это версия, а не время.
- Устаревший факт не удаляй: он остаётся в истории со ссылкой на актуальный.
```

## 6. Крайние случаи

| Случай | Поведение |
|---|---|
| Страница переименована или перемещена | `page_id` не меняется; обновить `title`, `space_key`, `ancestors` |
| Страница удалена | статус `удалена`; факты из неё не используются в ответе, только в истории |
| Изменились только вложения (скетчи) | если API отдаёт версии вложений — хранить их отдельно и сверять; иначе ставить `не сверено` |
| Дочерние страницы КАФО | каждая сверяется отдельно; в строке источника — та, из которой взят факт |
| Страница правят во время ответа | фиксировать версию в момент чтения; расхождение попадёт в следующий ответ, это нормально |
| Нет прав на метаданные | `не сверено` + указать, что нужен доступ на чтение |

## 7. Приёмочные проверки

1. Версия совпадает → ответ со статусом «свежо», без предупреждений.
2. Версия выросла на 2 → предупреждение с числом правок и ссылкой, факты переиндексированы.
3. Confluence недоступен → ответ со статусом «не сверено», таймаут не превышен.
4. Страница переименована → факты находятся по `page_id`, старое имя не ломает ссылки.
5. Устаревший факт после обновления → виден в истории, помечен `superseded_by`, в ответ не попадает.
6. Время ответа не выросло больше чем на 3 секунды на источник.

## 8. Чего не делать

- Не тянуть тело страницы для проверки версии.
- Не полагаться на `lastUpdated` как на единственный признак: правку могут откатить.
- Не удалять старые факты — история нужна для споров и аудита.
- Не блокировать ответ из-за недоступного Confluence.
- Не считать совпадение версии доказательством корректности: это доказательство актуальности, а не правоты.
