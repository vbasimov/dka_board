# mcp-email: что известно и что из этого следует

Источник: обезличенный обзор конфигурации и кода сервера `mcp-imap-mail` 1.0.0, получен 25.11.2026.

## 1. Как запускается

| Параметр | Значение |
|---|---|
| Конфигурация хоста | `~/.gigacode/settings.json`, ключ `mcpServers."mcp-email"` |
| Команда | `node <путь>/dist/index.js` |
| Транспорт | stdio; HTTP/SSE нет — подключиться к уже запущенному процессу нельзя |
| Учётные данные | переменные окружения `USER`, `PASSWORD`, `SMTP_FROM`, `LDAP_BIND_DN`, `LDAP_BIND_PASSWORD`; секреты вида `$secret:` разворачивает хост из системной ключницы |
| Настройки по умолчанию | `config.json`: IMAP 993 (TLS), SMTP 587, LDAP 636 |

**Следствие:** наш помощник должен запускать сервер сам и получать все переменные явно. Без явных значений секретов он не подключится.

## 2. Инструменты

`list_folders`, `list_messages`, `search_messages`, `read_message`, `send_email`, `get_unread_count`, `search_ldap`, `calendar_list_events`, `calendar_create_event`, `calendar_update_event`, `calendar_delete_event`, `search_local_archive`.

Ограничения: `limit` ≤ 100 (по умолчанию 20), пагинации нет — только «последние N». Поиск по отправителю на сервере не поддерживается: фильтрация на клиенте. Лимиты вызовов: поиск 10/мин, списки 30/мин, отправка 5/мин.

## 3. Чего нет

| Чего нет | Следствие для продукта |
|---|---|
| `Message-ID`, `In-Reply-To`, `References` | цепочки писем строим по теме без префиксов `Re:`/`FW:`; это приблизительно, интерфейс помечает способ группировки |
| Пометки письма прочитанным (нет STORE `\Seen`) | «не прочитано» — состояние на момент выгрузки, из программы его не изменить |
| HTML-тела и вложений | черновики и разбор только по тексту; вложения не анализируем |
| Черновиков (`save_draft`) | черновик живёт в нашем хранилище, отправка — вручную |
| Связи с индексом знаний | письма не попадают в sbm-search сами; нужен мост (сборщик документов) |

## 4. Что есть полезного

- `uid` и `folder` — стабильный ключ письма для дедупликации (лучше, чем `seq`).
- Даты приходят в UTC (`toISOString`), сравнение «ответ позже письма» корректно.
- Текст письма отдаётся целиком, лимит исходника 1 МБ.
- Флаг `\Seen` читается в списке (`●`) и в `read_message` (`Flags:`).
- Отправка поддерживается (`send_email`), но в v1 мы её не используем.

## 5. Как подключено у нас

```
AA_MAIL_CMD="node /путь/к/dist/index.js"   # обязательно
AA_MY_ADDRESSES="arch@example.com"          # чьи письма считать своими
AA_MAIL_FOLDER="INBOX"                      # папка по умолчанию
AA_INDEX_CMD="sbm-search index --incremental --dir /путь/к/базе"  # по желанию
```

Проверено на заглушке MCP-сервера: синхронизация 2 писем, мост записал 2 файла с фронтматтером. Настоящая почта в этой среде не подключалась и не нужна: настройка выполняется в закрытом контуре.

- `POST /api/email/sync` — забирает последние письма, читает первые `read` и складывает в локальное хранилище.
- `POST /api/email/bridge` — превращает письма в `md` с фронтматтером в каталог `письма-для-индекса` и (по флагу `index: true`) запускает индексацию командой из `AA_INDEX_CMD`.
- `GET /api/email/unanswered` — письма без ответа: группировка по теме, ответ — сообщение с моего адреса позже по времени.
- Сводка берёт «неотвеченные» из почты, если письма есть, иначе из задач.

## 6. Что нужно от владельца почты

1. Путь к `dist/index.js` в контуре.
2. Разрешение передать помощнику `USER`, `PASSWORD`, `SMTP_FROM` (значения секретов — вне git, через файл окружения).
3. Решение по мосту в индекс: писать письма в `md` с фронтматтером и индексировать, или искать по ним отдельно.

## 7. Риски

- **Ложная группировка по теме.** Письма «Согласование» от разных людей могут слипнуться. Компенсация: способ группировки виден в ответе (`threadBy: тема`), при появлении заголовков код автоматически переключается на них.
- **Устаревший флаг прочтения.** Мы не можем пометить письмо прочитанным, поэтому «не прочитано» может оставаться таковым, даже если человек прочёл письмо в почтовом клиенте.
- **Лимит 1 МБ.** Очень длинные письма обрезаются сервером; в интерфейсе это надо подписывать.
