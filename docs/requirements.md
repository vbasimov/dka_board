# Требования: ассистент архитектора (v0.1, для согласования)

Основание: [интент](product-intent-architect-assistant.md), [свежесть КАФО](cafo-cache-freshness-instruction.md), [разбор draw.io](drawio-recognition-instruction.md), [описание продукта](product-experience.md).
Горизонт: пилот на одном трайбе, 4 недели после 2 недель подготовки.

## 1. Бизнес-требования

| ID | Цель | Измеримый результат | Как проверим |
|---|---|---|---|
| BR-01 | Сократить время обоснования | медиана ≤ 20 минут от запроса до отправленного обоснования | журнал 10 запросов |
| BR-02 | Ускорить фиксацию решений | ≥ 80% решений недели в КАФО за ≤ 3 дня | дата решения и версия страницы |
| BR-03 | Не терять начатое | ≥ 80% незавершённых дел имеют сохранённый следующий шаг; потерю задач не измеряем — заказчик прямо сказал, что её нельзя посчитать | недельная выборка задач с полем «следующий шаг» |
| BR-04 | Быстрый старт | первый черновик ≤ 10 минут после установки | 5 новичков, хронометраж |
| BR-05 | Доверие к фактам | ≤ 10% утверждений с ошибкой | 20 ответов, ручная сверка |
| BR-06 | Принятие ответов | ≥ 50% отправлено без правок | пометка при отправке |
| BR-07 | Честная свежесть | 100% фактов со статусом, ложных «свежо» — 0 | аудит 50 источников |
| BR-08 | Разбор схем | ≥ 70% корректных рёбер, выдуманных — 0 | 10 схем, ручная сверка |
| BR-09 | Распространение | ≥ 2 установки без помощи автора | журнал установок |
| BR-10 | Окупаемость | поддержка ≤ 4 ч/нед при экономии ≥ 6 ч/нед | учёт часов и опрос |
| BR-11 | Изолированный контур | 0 внешних сетевых вызовов | перехват трафика, работа офлайн |

## 2. Функциональные требования

Приоритеты: **must** — обязательно для пилота, **should** — можно отложить, **could** — желательно.

### Реестр задач

- **FR-01 (must).** Захват из письма и файла: заголовок, источник, срок, тип. ≥ 70% на 30 письмах.
- **FR-02 (must).** Ввод бумаги и «из головы»: ≤ 2 действий, медиана ≤ 30 секунд на 10 задачах.
- **FR-03 (must).** Импорт из MCP/Jira и папок файлов, дедупликация по внешнему идентификатору; повторный импорт не создаёт дублей.
- **FR-04 (should).** Статусы, фильтры, поиск; ≤ 500 мс на 10 000 задач.
- **FR-05 (could).** Экспорт в Markdown/CSV с источником; открывается в Obsidian.

### Карточка внимания

- **FR-06 (must).** Экран «что делать сейчас»: пять первых элементов; следующий шаг находится ≤ 1 минуты.
- **FR-07 (must).** Приоритет: эскалация → срок → поручение руководителя; 15 эталонов, порядок совпадает на 100%.
- **FR-08 (must).** Просрочки и эскалации не скрываются: счётчик и метка на карточке.
- **FR-09 (should).** Строка «почему это здесь»: 100% карточек.
- **FR-10 (could).** Правила приоритета настраиваются конфигом.

- **FR-48 (must).** Синхронизация почты через mcp-email по stdio: список писем, чтение первых N, дедупликация по `folder + uid`.
- **FR-49 (must).** Мост «письма → индекс»: markdown с фронтматтером, идемпотентная запись, запуск индексации по флагу.
- **FR-50 (should).** Группировка писем в цепочки по теме, если заголовков нет; способ группировки виден в интерфейсе.
- **FR-46 (must).** Ежедневная проверка фактов в виде карточек: утверждение и источник, три ответа — «подтвердить», «недостоверно», «пропустить»; пропущенный факт возвращается не раньше следующего дня.
- **FR-47 (must).** «Продолжить»: у задачи можно сохранить следующий шаг одной кнопкой; блок на сводке показывает незавершённые дела и их шаг.
- **FR-45 (must).** Страница «Сводка»: на одном экране статусы КАФО по страницам, неотвеченные сообщения, задачи с горящим сроком на сегодня; счётчики по каждому блоку.

### Черновики ответов

- **FR-11 (must).** Письмо → черновик с 1–3 источниками; медиана ≤ 20 минут на 10 запросах.
- **FR-12 (must).** Каждое утверждение со ссылкой; без ссылки — «требует подтверждения».
- **FR-13 (must).** Автоматической отправки нет, только копирование.
- **FR-14 (should).** Структура ответа: позиция — обоснование — риски — следующий шаг; ≥ 50% без правок.
- **FR-15 (should).** Черновик сохраняется как решение в Markdown и открывается повторно.
- **FR-16 (could).** Шаблоны для 12 типовых запросов.

### КАФО и свежесть

- **FR-17 (must).** Кэш хранит `page_id`, `version`, `checked_at`, `url`, `ancestors`; 100% записей.
- **FR-18 (must).** Сверка только метаданных, таймаут 3 секунды; все 6 проверок инструкции проходят.
- **FR-19 (must).** Статус свежести в строке источника: 100% ответов.
- **FR-20 (must).** При росте версии: перекачка, переиндексация, `superseded_by`; старый факт не попадает в ответ.
- **FR-21 (must).** Confluence недоступен → «не сверено» за ≤ 3 секунды, ответ не блокируется.
- **FR-22 (should).** Переименование и перенос страницы: поиск по `page_id`, ссылки не ломаются.

### Схемы draw.io

- **FR-23 (must).** Четыре источника: `.drawio`, вложение, тело макроса, PNG с `mxfile` — 4 из 4.
- **FR-24 (must).** Мультистраничность и сжатые диаграммы (`inflateRaw`): 3 страницы = 3 диаграммы.
- **FR-25 (must).** Дерево зон по `parent`; ребро без `source`/`target` → `unparsed` с низкой уверенностью.
- **FR-26 (must).** Выход — JSON (зоны, узлы, рёбра, внешние системы, `unparsed`), валидируется схемой.
- **FR-27 (must).** Сверка с КАФО: три списка и «требует взгляда»; ≥ 70% рёбер, 0 выдуманных.
- **FR-28 (must).** Скриншот или фото → «не распознано» с причиной; распознавания картинок нет.
- **FR-29 (should).** Свежесть вложения по версии или хэшу; синонимы — кандидаты на объединение, не склейка.

### Версии фактов

- **FR-30 (must).** Факт: идентификатор, утверждение, источник, версия, дата, статус, `superseded_by`.
- **FR-31 (must).** Устаревший факт не удаляется, остаётся в истории со ссылкой.
- **FR-32 (must).** В ответе только актуальные факты; устаревшие — по запросу «история».
- **FR-33 (should).** Двусторонняя ссылка «заменён на».

### Недельное ревью

- **FR-34 (must).** Отчёт: что произошло и что не учли (интеграции, устаревшие факты, объекты без движения) по чек-листу.
- **FR-35 (must).** Отдельный скилл по расписанию, результат — Markdown-файл.
- **FR-36 (should).** Ручной запуск и правка отчёта; правки сохраняются.

### Плагины

- **FR-37 (must).** Контракт: манифест, точка расширения, версия API, права.
- **FR-38 (must).** Сетевые вызовы плагина запрещены; отказ и запись в журнал.
- **FR-39 (should).** Падение плагина не роняет ядро; тест с падающим плагином.
- **FR-40 (could).** Совместимость в пределах мажорной версии; миграция описана.

### Установка и обновление

- **FR-41 (must).** Один архив, без интернета и прав администратора; ≤ 10 минут до первого черновика.
- **FR-42 (must).** Проверка целостности и версии бандла; подмена обнаруживается.
- **FR-43 (must).** Обновление без потери данных: реестр и факты целы.
- **FR-44 (should).** Откат на предыдущую версию ≤ 15 минут.

## 3. Нефункциональные требования

| Категория | Требование и критерий |
|---|---|
| Производительность | 10 000 задач, 5 000 фактов; старт ≤ 3 с, поиск ≤ 500 мс, карточка ≤ 1 с; офлайн — всё, кроме сверки версий |
| Надёжность | Confluence недоступен → «не сверено» ≤ 3 с; сбой плагина не роняет ядро; модель недоступна → ручной режим; восстановление ≤ 5 мин |
| Безопасность | 0 внешних сетевых вызовов (перехват и анализ зависимостей); без CDN и телеметрии; данные в выбранной папке; в логах нет тел писем |
| Совместимость | Windows 10/11, macOS 13+, Linux x86_64; Chrome/Edge/Firefox текущей и предыдущей версии; CommonMark + YAML; хранилище Obsidian без плагина; ≤ 150 МБ |
| Удобство | первый результат ≤ 10 мин у 5 из 5; клавиатурная навигация; контраст ≥ 4,5:1, масштаб 200%; сообщения об ошибках на русском |
| Поддерживаемость | обновление и откат ≤ 15 мин без потерь; must-требования покрыты тестами ≥ 80%; сборка ≤ 10 мин; контракт плагина версионирован |
| Локализация | 100% интерфейса на русском; даты ДД.ММ.ГГГГ, локальный часовой пояс; глоссарий (КАФО, ФО, трайб); UTF-8 |

## 5. Что в требованиях пока не определено

| Пробел | Почему блокирует | Кто решает |
|---|---|---|
| Определение «потерянной задачи» | без него BR-03 неизмерим | заказчик |
| Канал попадания писем (MCP почты или копирование) | влияет на FR-01 и обещание 20 минут | заказчик + ИБ |
| Онтология факта: поля, срок жизни, кто подтверждает | ядро D4/D15, без него нет версий | заказчик |
| Поведение без модели | влияет на NFR «Надёжность» | владелец продукта |
| Ответственность за чужие плагины | влияет на FR-37–FR-40 | заказчик |
| Классификация и шифрование папки данных | влияет на NFR «Безопасность» | ИБ |
| Критерий «принято без правок» | без него BR-06 субъективен | заказчик |
