# Инструкция: распознавание скетчей draw.io

Кому: владельцу скилла выгрузки КАФО.
Что сделать: научить скилл извлекать из скетчей структуру (компоненты, зоны, интеграции), а не «смотреть картинку».
Почему это ключ: пропущенная интеграция — самый частый тип промаха после утверждения архитектуры. Если скетч разобран в граф, интеграции можно сверить с КАФО автоматически.

---

## 1. Главное правило

Скетч — это не картинка, а **XML-структура**. Всё, что нужно, лежит в `mxGraphModel`: вершины, рёбра, подписи, контейнеры. Распознавание картинки (OCR/vision) — запрещённый путь: дорого, врёт и не даёт связей. Сначала XML; картинка — только чтобы честно сказать «не разобрано».

## 2. Где искать диаграммы

| Источник | Признак | Как достать |
|---|---|---|
| Файл `.drawio` | расширение | читать как XML напрямую |
| Вложение на странице Confluence | draw.io-макрос | `GET /rest/api/content/{pageId}/child/attachment?expand=version`, брать вложения `*.drawio` |
| Тело макроса | `<ac:structured-macro ac:name="drawio">` | параметры `diagramName` / `diagramDisplayName` → имя вложения; если тело макроса содержит `<mxfile>` — брать оттуда |
| PNG с встроенным XML | `*.drawio.png` | в PNG-чанке `tEXt` с ключом `mxfile` лежит XML; прочитать чанки, достать текст |
| Скриншот / фото | нет XML | `не распознано`, показать причину; не выдумывать схему |

## 3. Разбор формата

### Структура

```xml
<mxfile>
  <diagram id="..." name="Платежи">
    <mxGraphModel><root>
      <mxCell id="0"/><mxCell id="1" parent="0"/>
      <mxCell id="2" value="Kafka" style="shape=cylinder3;..." vertex="1" parent="1">
        <mxGeometry x="40" y="40" width="80" height="60" as="geometry"/>
      </mxCell>
      <mxCell id="3" value="CRM" vertex="1" parent="1"/>
      <mxCell id="4" edge="1" source="2" target="3" style="edgeStyle=orthogonalEdgeStyle;dashed=1"/>
    </root></mxGraphModel>
  </diagram>
</mxfile>
```

### Обязательные шаги

1. **Мультистраничность.** В `mxfile` может быть несколько `<diagram>`; каждая — отдельная схема со своим именем. Не склеивать: у каждой свой `name` (он же — имя скетча в ссылке).
2. **Сжатие.** Если внутри `<diagram>` не XML, а строка base64 (обычно начинается на `7V`), распаковать: `inflateRaw` → `decodeURIComponent` → XML. Без этого половина файлов «не парсится».
3. **Контейнеры.** `parent` задаёт иерархию: контейнеры — это зоны, трайбы, ФО. Строить дерево `parent → children`, а не плоский список.
4. **Рёбра.** `edge="1"` + `source`/`target` — это интеграция. Если `source`/`target` пустые (ребро «приклеено» к точке или нарисовано руками), искать ближайшую вершину по геометрии и помечать `confidence: low`.
5. **Подписи.** `value` может содержать HTML (`<b>`, `<br>`, `&nbsp;`) — очищать, сохраняя переводы строк.
6. **Стили.** Из `style` вытащить: `shape=`, `dashed=1`, `strokeColor`, `fillColor`, `swimlane`.
7. **Группы.** `group=1` — визуальная группа, не зона; зоной считать контейнер с `swimlane` или с `parent`, у которого есть подпись.

## 4. Как маппить стили в типы

Не угадывать по названию («Kafka» ≠ автоматически очередь), а брать подсказки из формы и подписи:

| Признак в draw.io | Тип |
|---|---|
| `shape=cylinder3`, `shape=datastore`, `shape=database` | хранилище |
| `shape=ellipse` + подпись «клиент/пользователь» | актор |
| `shape=cloud` | внешняя система |
| `shape=hexagon`, `shape=step` | сервис/процесс |
| `dashed=1` на ребре | асинхронный поток |
| `swimlane` | зона ответственности |

Если в стиле ничего нет — тип `неизвестно` и `confidence: low`. Лучше честный «неизвестно», чем выдуманный «сервис».

## 5. Нормализованный выход

```json
{
  "source": {"type": "confluence_attachment", "page_id": "123", "attachment": "Платежи.drawio", "version": 4},
  "diagram": {"name": "Платежи", "page": 1},
  "zones": [{"id": "z1", "label": "ФО Платежи", "parent": null}],
  "nodes": [{"id": "2", "label": "Kafka", "kind": "очередь", "zone": "z1", "confidence": "high"}],
  "edges": [{"from": "2", "to": "3", "label": "события", "sync": false, "confidence": "high"}],
  "external": ["CRM"],
  "unparsed": [{"id": "9", "reason": "edge без source/target"}]
}
```

Этот JSON — единственное, что видят остальные модули: ревью, поиск, версии фактов.

## 6. Сверка с КАФО

Главная ценность. Для каждой диаграммы:

1. Взять список интеграций из КАФО (страница + кэш).
2. Сравнить с рёбрами, у которых оба конца — компоненты.
3. Выдать три списка: **в схеме, но не в КАФО**; **в КАФО, но не в схеме**; **совпало**.
4. Пограничные случаи (ребро с `confidence: low`, внешняя система, зона без подписи) — в отдельный список «требует глазами», а не в «пропущено».

Это и есть ответ на боль «утвердили архитектуру, а потом прибежали с забытой интеграцией».

## 7. Свежесть

- У вложения Confluence есть своя `version` — хранить её и сверять так же, как версию страницы.
- У файла — хэш содержимого; при изменении хэша переиндексировать.
- В ссылке указывать: страница, имя диаграммы, страница внутри диаграммы (если мультистраничная), версия вложения, дата разбора.

## 8. Ограничения, которые надо признать

- Скриншот или фото схемы — `не распознано`, предложить попросить исходник.
- Рукописные элементы, картинки вместо фигур, вставленный текст без структуры — `неизвестно`.
- Диаграммы, нарисованные не в draw.io, — вне области: конвертировать нельзя, честно помечать.
- Один и тот же компонент с разными подписями («Kafka», «кафка», «Kafka Cluster») — нормализовать по словарю и показывать кандидатов на объединение, а не склеивать молча.

## 9. Приёмочные проверки

1. Файл `.drawio` с одной страницей → узлы, рёбра, подписи извлечены без потерь.
2. Файл с тремя страницами → три отдельные диаграммы, не смешаны.
3. Сжатая диаграмма (base64) → распакована и разобрана.
4. Вложение на странице Confluence → найдено по макросу, версия вложения сохранена.
5. Контейнеры «трайб → ФО» → дерево зон восстановлено, узлы привязаны к зонам.
6. Ребро без `source`/`target` → попало в `unparsed`, а не выдумано.
7. Схема с интеграцией, которой нет в КАФО → попала в список «в схеме, но не в КАФО».
8. PNG-скриншот → `не распознано` с причиной, без выдуманных компонентов.

## 10. Фрагмент для SKILL.md

```markdown
## Скетчи draw.io

Скетчи всегда в draw.io: файлом или вложением на странице Confluence.

- Источник структуры — XML (`mxGraphModel`), а не картинка. Картинку не распознавать, а честно помечать «не распознано».
- Мультистраничные файлы разбирать по одной диаграмме; имя страницы — часть ссылки.
- Сжатые диаграммы (base64 в `<diagram>`) распаковывать `inflateRaw` + `decodeURIComponent`.
- Контейнеры (`parent`) — это зоны; строить дерево, а не плоский список.
- Рёбра (`edge`) — интеграции; без `source`/`target` — в `unparsed`, не выдумывать.
- Тип компонента брать из стиля и подписи; при отсутствии признаков — `неизвестно`.
- Результат — нормализованный JSON (зоны, узлы, рёбра, внешние системы, unparsed).
- Сверять рёбра с интеграциями КАФО: три списка — только в схеме, только в КАФО, совпало; пограничные случаи отдельно.
- Свежесть — по версии вложения или хэшу файла.
```
